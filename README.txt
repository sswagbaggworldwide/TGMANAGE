Telegram Manager — пары .session + .json, Windows, Python 3.10 (64-bit)

Установщик setup.exe, хранение данных и выпуск обновлений описаны в README.md.
В установленной версии личные данные находятся в %LOCALAPPDATA%\TelegramManager.
При запуске исходников через start.bat они остаются рядом с app.py.

ГЛАВНАЯ / ДАШБОРД
Первая вкладка показывает состояние программы в реальном времени: количество
файлов сессий, работающие аккаунты, отправленные сообщения, ошибки, недоступные
аккаунты и вступления в каналы. В журнале дашборда
видны основные события текущего запуска. Показатели отправок, ошибок и
вступлений обнуляются при новом запуске программы. Кнопки быстрого доступа
открывают соответствующие рабочие вкладки.

ЛОГИ И ОШИБКИ РАССЫЛКИ
Каждый запуск автоматически создаёт UTF-8 файл в папке logs внутри папки данных.
Имя содержит дату и время запуска, например telegram_manager_2026-11-13_12-30-00.log.
Кнопка «Папка логов» на главной открывает эту папку. В файл попадают основной
журнал, статусы аккаунтов, парсер, лайки и системные ошибки; секреты API в него
не записываются.
Ожидаемые постоянные ограничения Telegram считаются пропусками, а не сбоями:
запрет писать в чат, ограниченный чат, закрытый топик и требование платной
отправки Stars. Программа не соглашается на платную отправку автоматически.
После первого такого ответа чат исключается из следующих кругов текущего задания.
На карточке «Ошибки / пропуски» первое число — неожиданные ошибки, второе —
чаты с постоянными ограничениями. Причина каждого пропуска остаётся в логе.
Постоянные ограничения также сохраняются в failed_chats.json. Кнопка
«Проблемные чаты» на главной открывает список с аккаунтом, названием, ID и
причиной. Можно выйти из выбранных чатов или из всего списка. Перед выходом
программа требует подтверждение; действие необратимо. Аккаунты должны быть
подключены, а их рассылка остановлена. Успешно покинутые и уже отсутствующие
чаты автоматически удаляются из списка. Кнопка «Убрать выбранные из списка»
не выходит из Telegram-чатов, а удаляет только локальные записи.

ЛАЙКИ @LEOMATCHBOT
Отдельная вкладка работает с выбранными на ней аккаунтами (Ctrl / Shift).
1. Загрузите аккаунты на первой вкладке. На вкладке лайков выберите нужные.
2. В Telegram вручную откройте просмотр анкет в @leomatchbot.
3. Настройки кнопок: лайк ❤️, пропуск рекламы 👎Не интересно, новый круг 1🚀.
   Кнопки лайка и рекламы нажимаются, включая встроенные кнопки сообщения.
   При новом круге нажимается доступная кнопка 1🚀; если она не прикреплена
   к последнему сообщению, отправляется её текст как команда клавиатуры.
   Фразы, обозначающие окончание лайков и запрос верификации, задаются через |.
   Верификация распознаётся по началу «Для верификации анкеты отправь видео-кружок».
   Фраза окончания лайков пока шаблон «лайки закончились»: точный ответ бота
   ещё нужно добавить при его появлении. Незнакомый ответ останавливает аккаунт
   и выводится в журнал для уточнения настройки.
4. Задайте паузу между лайками и нажмите «Запустить выбранные».
5. После сообщения о лимите статус аккаунта: «лайки закончились, начну круг
   снова когда они возобновятся (через сутки)». Через 24 часа программа отправит
   настроенную команду нового круга и продолжит обработку ответов.
6. При запросе верификации аккаунт останавливается, выделяется красным,
   в журнале появляется сообщение с файлом его сессии; подаётся звуковой сигнал.
   Пройдите проверку вручную в Telegram и запустите этот аккаунт снова.
   Остальные выбранные аккаунты работают независимо.
«Стоп выбранных» и «Стоп всех лайков» отменяют также суточное ожидание.
Рассылки по направлениям и лайки управляются отдельно.
Срок ожидания и пометки верификации сохраняются в bot_likes_state.json;
настройки и выбор аккаунтов — в bot_likes_settings.json.
Закрытая программа не выполняет задания. После открытия загрузите аккаунты
и нажмите запуск: ещё не истёкшее ожидание продолжится с сохранённого срока.
Повторно открыть программу раньше срока не означает сброс лимита.
Кнопки нажимаются только при точном совпадении с настройкой. Неизвестный
экран, отсутствие кнопки, таймаут или ошибка останавливают аккаунт для ручной
проверки. Если бот не присылает клавиатуру вместе с каждой анкетой, требуется
адаптация по реальным примерам диалога. Успешная работа именно с текущим
интерфейсом бота требует проверки настроек по его сообщениям.
При обновлении сохраняйте оба файла bot_likes_*.json.

НАПРАВЛЕНИЯ РАССЫЛКИ
Вкладка «Аккаунты и отправка» теперь сохраняет отдельные направления.
У каждого направления свои аккаунты, режим отправки, источник и все три паузы.
1. Загрузите аккаунты. При первом запуске прежние тексты из texts.json
   появятся в направлении «Основное».
2. Создайте направление кнопкой «+ Направление», например «Недвижимость».
3. Выберите его аккаунты вручную через Ctrl / Shift либо введите количество
   и нажмите «Выбрать свободные». Эта кнопка выбирает первые N подключённых
   аккаунтов, не закреплённых за другими направлениями и не занятых рассылкой.
   Если свободных аккаунтов недостаточно, выбор остаётся прежним.
4. Выберите режим направления: «Готовые тексты» или «Пересылка сообщения».
   В первом режиме добавьте тексты и задайте порядок. Во втором вставьте ссылку
   на один пост из канала. Затем задайте паузы.
5. Нажмите «Запустить направление». Затем переключитесь на другое направление,
   выберите другие аккаунты и настройки отправки и запустите его. Обе рассылки работают
   одновременно. Колонка «Направление / работает» показывает назначения
   аккаунтов, а знак ▶ — направление текущей рассылки.
6. «Стоп направления» останавливает все задания открытого направления,
   включая отложенные старты, независимо от текущего выделения аккаунтов.
   «Стоп выбранных» и «Стоп всех» также доступны.
Направления сохраняются в directions.json при переключении, запуске,
закрытии и по кнопке «Сохранить направления». После перезапуска загрузите
аккаунты заново: выбор восстановится. Рассылки автоматически не запускаются.
Правки режима, текстов, ссылки, аккаунтов и пауз применяются при следующем запуске.
Если хотя бы один выбранный аккаунт уже работает, новый запуск целиком
отменяется с сообщением: сначала остановите его или измените выбор.
Ручной выбор позволяет использовать аккаунт в разных направлениях по очереди.
Перед удалением направления остановите его рассылку. Удаление убирает его
настройки и тексты. Файлы Telegram-аккаунтов не удаляются.
При обновлении сохраняйте directions.json вместе с остальными данными.
Исходный texts.json при переходе сохраняется; далее настройки рассылок
читаются из directions.json. Описание единого набора текстов ниже относится
к прежней версии; порядок ротации и отправка во все группы остаются прежними.

ПЕРЕСЫЛКА СООБЩЕНИЯ ИЗ ПРИВАТНОГО КАНАЛА
1. Добавьте все используемые аккаунты в приватный канал.
2. В настройках канала выключите защиту содержимого / запрет копирования.
   При включённой защите Telegram не разрешит переслать пост.
3. Откройте нужный пост, выберите «Копировать ссылку на сообщение» и вставьте
   ссылку в поле «Ссылка на сообщение». Для приватного канала она обычно имеет
   вид https://t.me/c/1234567890/123.
4. Выберите режим «Пересылка сообщения» и запустите направление.
Каждый выбранный аккаунт использует этот же пост и пересылает его во все свои
группы. Пересылка сохраняет подпись исходного канала. Пользователь, который не
состоит в приватном канале, не получает доступ к его содержимому через подпись.
Пост передаётся Telegram по ID без загрузки его содержимого в программу, поэтому
поддерживаются также сообщения в формате статьи и другие новые форматы.
Если аккаунт не добавлен в канал, пост удалён или пересылка запрещена, этот
аккаунт остановится, а причина появится в журнале. Готовые тексты продолжают
работать в отдельном режиме без изменений.

ВСТУПЛЕНИЕ В ОТКРЫТЫЙ КАНАЛ
1. На вкладке «Аккаунты и отправка» выделите нужные аккаунты через Ctrl / Shift.
2. Вставьте публичную ссылку вида https://t.me/channel_name в поле
   «Открытый канал» и нажмите «Вступить выбранными».
3. Результат для каждого аккаунта появится в журнале.
Функция принимает только открытые каналы. Публичные группы и приватные ссылки
вида https://t.me/+... отклоняются. Уже подписанные аккаунты считаются успешно
обработанными. Telegram может ограничить частые массовые вступления FloodWait;
в этом случае программа покажет ожидание и продолжит после указанной паузы.

УПРАВЛЕНИЕ АККАУНТОМ
После «Загрузить аккаунты» нажмите правой кнопкой на нужный аккаунт во вкладке
«Аккаунты и отправка». В открывшемся окне можно отдельно сменить юзернейм,
био и имя профиля, отключить общие уведомления от личных чатов и групп, скрыть
время последнего захода для всех и запретить входящие звонки для всех.
Каждое действие применяется к выбранному аккаунту после нажатия своей кнопки.
Пустой юзернейм удаляет текущий, пустое био очищает описание (с подтверждением).
Поле «Имя профиля» меняет имя; фамилия остаётся прежней.
Индивидуальные исключения уведомлений для отдельных чатов сохраняются.
В поле для папок вставляйте ссылки вида https://t.me/addlist/... по одной на
строке и нажмите «Добавить папки». Telegram добавит доступные чаты и саму
общую папку. Результат каждой ссылки показывается в окне. Кнопка
«Остановить» прерывает оставшиеся ссылки, но не удаляет уже добавленные папки.
Двойной щелчок по аккаунту открывает папку его файла .session в Проводнике.
Если Telegram разорвёт соединение, менеджер покажет это в статусе аккаунта и
попробует восстановить связь автоматически с увеличивающейся паузой между
попытками. Перед действиями этого окна соединение также проверяется и при
необходимости восстанавливается. Если сессия больше не авторизована, нужен
повторный вход в Telegram. При ошибке связи после отправки команды проверьте
настройку перед повтором: Telegram мог успеть применить её до разрыва.

НОВОЕ: БАЗА ПОЛЬЗОВАТЕЛЕЙ
1. Загрузите свои аккаунты на вкладке «Аккаунты и отправка».
2. Откройте «База пользователей», выберите один подключённый аккаунт.
3. Нажмите «Загрузить чаты», выделите нужные группы (Ctrl / Shift).
4. Введите ключевые слова или фразы, каждое с новой строки.
   Совпадение по подстроке, регистр не важен: «модел» найдёт «модель» и «модели».
   Достаточно любого из указанных ключей. Повторяющиеся пробелы и е/ё
   нормализуются. Это обычный текстовый фильтр, без ИИ, токенов и API ИИ.
   Он не определяет намерение автора: «ищу модель» и «продаю модель»
   оба совпадут с ключом «модель». Для точного отбора задавайте фразы.
5. Для старых объявлений оставьте «Собрать историю при старте».
   По умолчанию проверяется 1000 последних сообщений каждого выбранного чата.
   Ноль означает всю доступную аккаунту историю; это может занять долгое время.
   Снимите галочку, если нужны только новые сообщения с момента включения.
6. Нажмите «Включить парсер». Мониторинг новых сообщений начинается сразу,
   до чтения истории. Новые сообщения проходят тот же фильтр ключевых слов.
   Пока программа открыта и парсер включён, база пополняется автоматически.
7. «Стоп» выключает мониторинг и чтение истории, сохраняя собранную базу.
   Автоматического запуска при открытии приложения нет.
8. «TXT: @username» сохраняет уникальные публичные username, по одному в строке.
   Пользователи без username остаются в базе; «CSV: вся база» включает их ID,
   имя, последнее совпавшее объявление, ключ и доступную ссылку на сообщение.
   В интерфейсе показывается до 1000 пользователей. Экспорт включает всю базу.
   В таблице можно выбрать автора и посмотреть текст объявления.

База: parser_users.sqlite3 внутри папки данных. Дубли исключаются по
Telegram ID во всех чатах, аккаунтах и запусках. Один и тот же автор может
оставить несколько объявлений, но в базе будет одна строка. Счётчик объявлений
не увеличивается при повторном чтении одного сообщения. Смена username
обновляет существующую запись при следующем совпавшем сообщении.
Пользователи-боты, удалённые аккаунты, свои сообщения и объявления от имени
канала / анонимного администратора пропускаются. У пересланного объявления
собирается текущий отправитель, а не автор пересланного оригинала.
Username, упомянутые в самом тексте объявления, не собираются.
В обычной приватной группе прямая ссылка на сообщение может отсутствовать.
База хранит последнее по дате совпавшее объявление каждого автора.

Настройки парсера сохраняются в parser_settings.json. При перезапуске
снова загрузите аккаунт и чаты, затем включите парсер; уже собранные авторы
сохраняются. Смена ключевых слов не очищает накопленную общую базу.
История доступна только в пределах доступа выбранного аккаунта.
Сообщения за время, когда парсер выключен, можно собрать повторным чтением
истории достаточной глубины. Изменённые старые сообщения сами по себе не
обрабатываются как новые; они могут попасть при следующем чтении истории.
При FloodWait программа ждёт указанное Telegram время; Стоп отменяет ожидание.
Ошибки доступа отображаются в журнале. Временная ошибка чтения автора
повторяется до двух раз. После окончательного отключения аккаунта парсер
останавливается; нажмите «Загрузить аккаунты» и включите его повторно.
При невозможности записать базу сбор останавливается с сообщением об ошибке.
При сбое экспорта ранее существовавший файл выгрузки не затирается.
Парсер не вступает в группы и
не отправляет сообщения. Вкладка отправки в группы работает отдельно.

ОБНОВЛЕНИЕ СТАРОЙ УСТАНОВКИ
Закройте старую программу. Замените файлы программы из этого архива,
сохранив свои accounts, config.json и texts.json. Добавлены user_parser.py
и parser_ui.py. Запуск через start.bat. Для версии EXE пересоберите на Windows
через build_exe.bat и перенесите существующие пользовательские данные к EXE.
Сохраните parser_users.sqlite3 и parser_settings.json при будущих обновлениях.


1. Установите Python 3.10 (64-bit), включив Add Python to PATH.
2. Распакуйте архив в доступную для записи папку.
3. Положите пары файлов в accounts, например:
   accounts/123456.session
   accounts/123456.json
   accounts/654321.session
   accounts/654321.json
   Допускаются вложенные папки. Имена в каждой паре должны совпадать.
4. Запустите start.bat. Первый запуск требует интернета для зависимостей.
5. Нажмите «Загрузить аккаунты». При наличии app_id/app_hash в JSON
   общие API ID/hash в окне заполнять не нужно.
6. Выберите режим «Готовые тексты» и добавьте тексты через «+ Добавить текст»:
   каждый текст — отдельная вкладка. Пустые вкладки пропускаются. Настройки
   сохраняются в directions.json кнопкой «Сохранить направления».
7. Выберите режим:
   По очереди: 1 → 2 → 3 → 1; очередь продолжается между кругами.
   Случайный порядок: все тексты перемешиваются, каждый используется один
   раз в наборе; затем набор перемешивается заново. На границе наборов
   возможен повтор одного текста.
   На каждую группу отправляется один текст. У каждого аккаунта своя очередь.
8. Выберите один или несколько подключённых аккаунтов (Ctrl / Shift), затем
   «Запустить». Сообщения идут во ВСЕ группы аккаунта, включая архивные,
   возвращённые Telegram. Личные чаты и каналы не включаются. Список групп
   автоматически обновляется в начале каждого круга. Выбора групп нет.
   Поле «Пауза между стартами аккаунтов» задаёт задержку перед запуском
   следующего выбранного аккаунта: первый стартует сразу, остальные — через
   указанное число секунд друг за другом. При 0 все стартуют одновременно.
   Ожидающие аккаунты видны по статусу «Запуск через ...». «Стоп выбранных»
   и «Стоп всех» отменяют также запланированные, ещё не начатые отправки.
9. Пауза между кругами 0 означает один круг. Другие значения включают
   повторение. Стоп выбранных / Стоп всех прерывает также ожидание FloodWait.
   Уже доставленные сообщения кнопка Стоп не удаляет. Изменения текстов и
   режима применяются при следующем запуске задания: остановите и запустите
   аккаунт снова. При перезапуске очередь начинается заново.
   Ошибка группы пропускает её и выбранный для неё текст; FloodWait повторяет
   тот же текст после ожидания. При таймауте отправка не повторяется, поскольку
   сообщение уже могло быть доставлено.

Из соседнего JSON читаются app_id/app_hash (или api_id/api_hash), device,
sdk, app_version, lang_pack, system_lang_pack, ipv6. Параметры устройства
сохраняются из файла, новые случайные параметры не генерируются.
Поля twoFA, phone, session_file и остальные не используются для авторизации:
аккаунт определяется содержимым .session. Программа не выводит секреты JSON.
Без JSON нужны общие API ID/hash, использованные при создании сессии.
Повреждённый JSON приводит к ошибке аккаунта, а не к скрытой замене настроек.
Поддерживаются только SQLite-сессии Telethon. Pyrogram, StringSession,
отозванные сессии не поддерживаются. Расширение .session само
по себе не гарантирует совместимость. Неавторизованные сессии требуют входа
вне программы. Коды и пароль 2FA программа не запрашивает.

Закройте другие программы с этими же сессиями. Не запускайте две копии
менеджера. Сессии могут обновляться Telethon при подключении; сохраните
резервную копию исходных файлов перед первым использованием.
Не передавайте accounts и config.json другим людям: сессии дают доступ
к аккаунтам. Используйте разрешённые публикации. FloodWait соблюдается.

Установщик: запустите build_setup.bat на Windows с установленным Inno Setup.
Результат: release/setup.exe. Сборка только EXE: build_exe.bat; результат
внутри release/build-*/dist/TelegramManager. Переносится вся папка с EXE.
Личные данные установленной версии находятся в %LOCALAPPDATA%\TelegramManager,
а при запуске start.bat — рядом с app.py. Аккаунты, настройки API и базы
в дистрибутив не входят. Подробнее о сборке и обновлениях — в README.md.

ОФОРМЛЕНИЕ «ГОЛОГРАФИЧЕСКИЙ ЦЕНТР»
Все вкладки используют чёрно-зелёную тему. На «Главной» показаны реальные
показатели запуска, журнал событий и GIF-сфера из assets/sphere-3d-360.gif.
График динамики и накопление его истории полностью удалены.
Переключатель «Декор» управляет декоративными рамками. Переключатель
«Анимация» ставит GIF на паузу; выбор сохраняется в ui_preferences.json.
GIF проигрывается только при видимом дашборде и останавливается при переходе
на другую вкладку или сворачивании окна. Кадры готовятся в фоне.
Во вкладке «Аккаунты и отправка» длинная форма прокручивается, а кнопки
запуска и остановки закреплены сверху.

ПАМЯТЬ И ДЛИТЕЛЬНАЯ РАБОТА
Для обычной рассылки входящие обновления Telegram отключены. Парсер и лайки
включают их только на нужном аккаунте и выключают после остановки; при
совместной работе одного аккаунта события остаются включены для второй задачи.
Фоновая синхронизация истории чатов для рассылочных аккаунтов остановлена.
Их временный кэш в оперативной памяти очищается при минутном обслуживании.
Сессионные файлы и сохранённые в них данные авторизации не удаляются.
Полные объекты последних сообщений из всех чатов освобождаются до начала
долгого круга рассылки: остаются только ID и названия нужных чатов.
Шифрование использует нативный cryptg, устанавливаемый через start.bat.
Экранный журнал ограничен, однотипные статусы объединяются, счётчики
отправок сохраняют точные значения. Полный файловый журнал пишется отдельно
от окна. При задержке диска его буфер ограничен 4 МиБ; при переполнении
в журнал добавляется явная запись log_overflow о пропущенных строках.
Регулярное сохранение проблемных чатов выполняется в фоновом потоке.
Раз в минуту в logs/telegram_manager_...log записывается строка [health]:
private_mb, размеры очередей, кэшей, число задач и задержка интерфейса.
Если окно не обрабатывает события более 10 секунд, диагностика сохраняет
стеки потоков с пометкой [ui_stall] (не чаще раза в минуту).
После обновления полностью закройте прежний процесс и запустите start.bat.

КОНВЕРТЕР TDATA (отдельная вкладка)
1. Закройте Telegram Desktop с исходной tdata и сохраните её резервную копию.
2. Откройте вкладку «Конвертер tdata», выберите tdata или её родительскую папку.
3. Если установлен локальный пароль Desktop, введите его. Это не облачный 2FA.
4. Нажмите «Конвертировать». Интернет для самого преобразования не нужен.
5. В accounts появится новая папка import_... с парами account_1.session/json
   и далее для всех доступных аккаунтов. Старые файлы не перезаписываются.
6. Перейдите на первую вкладку и нажмите «Загрузить аккаунты».

Конвертер использует существующий ключ авторизации и профиль Telegram Desktop.
Он не создаёт новую независимую авторизацию: завершение исходной сессии в
Telegram может сделать экспорт непригодным. Не используйте одновременно
исходную tdata и экспортированные пары в разных программах.
JSON содержит настройки API/устройства, но не пароли. Исходная папка не
изменяется. Конвертер не проверяет на сервере, действителен ли ключ: эта
проверка происходит при загрузке аккаунтов. Полнота/совместимость tdata
определяется актуальной библиотекой opentele2. При ошибке смотрите журнал
отдельной вкладки. Поддерживается современный формат Telegram Desktop 7.3.x.

Для конвертера используется готовый модуль opentele2 для Windows.
Microsoft Visual C++ Build Tools не требуются.

Вставка текста: Ctrl+V поддерживает русскую и английскую раскладку Windows.
Также доступны кнопка «Вставить» и меню правой кнопки мыши.

Диагностика конвертера показывает подробную причину и цепочку ошибок чтения.
Пароль маскируется. При ошибке пришлите текст журнала, а не саму tdata.

ПОИСК ГРУПП
Загрузите аккаунты на первой вкладке, затем откройте «Поиск групп».
Выберите аккаунт и введите запросы, каждый с новой строки (от 3 символов).
Начните поиск. Экспорт: Excel, CSV, TXT со ссылками.
Telegram возвращает ограниченную подборку публичных групп. Это не полный каталог.
Каналы исключаются; программа не вступает в найденные группы.
При FloodWait поиск ждёт указанное Telegram время. Стоп отменяет ожидание.
Для обновления закройте старую программу, замените файлы программы и запустите start.bat.
Свои accounts, config.json и texts.json сохраните. Для EXE заново выполните build_exe.bat.

Поиск с нескольких аккаунтов: отметьте «В работе» рядом с нужными аккаунтами.
«Выбрать все» / «Снять выбор» управляют отметками. Поиск запускается параллельно.
Выбор фиксируется на время поиска; чтобы поменять его, нажмите Стоп.
Дубликаты объединяются по ID группы; колонка «Аккаунты» показывает источники.
FloodWait ожидается отдельно каждым аккаунтом. Стоп останавливает всех.
