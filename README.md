# Telegram Manager

Программа для Windows 10/11 x64. Python для установки не требуется.

Скачайте **setup.exe** из [последнего релиза](https://github.com/sswagbaggworldwide/TGMANAGE/releases/latest) и запустите установку. Аккаунты и личные настройки в дистрибутив не входят.

## Данные и обновления

Установленная программа хранит аккаунты в `%LOCALAPPDATA%\TelegramManager\accounts`, логи — в `%LOCALAPPDATA%\TelegramManager\logs`. Кнопка «Папка accounts» открывает нужную папку. При переходе с исходников перенесите свои сессии и соседние JSON туда вручную. Настройки из прежней папки можно перенести туда же при закрытой программе.

Кнопка **Обновления** проверяет GitHub Releases. Доступная версия появляется отдельным окном. **Установить обновление** скачивает установщик, проверяет SHA-256, предлагает сохранить данные и завершить работу, затем устанавливает версию в ту же папку и снова запускает приложение. Проверка также выполняется после запуска и каждые 6 часов; её можно отключить в окне обновлений.

Обновление и удаление программы сохраняют пользовательскую папку с аккаунтами, настройками и логами. Токен GitHub для проверки не нужен; репозиторий и релизы должны быть публичными.

## Запуск из исходников

Установите Python 3.10 x64 и запустите `start.bat`. В этом режиме данные остаются рядом с `app.py`. Существующий функционал описан в [README.txt](README.txt).

## Сборка установщика

Установите [Inno Setup 6 или 7](https://jrsoftware.org/inno-setup/downloads) и запустите `build_setup.bat`. Если компилятор установлен в другом месте:

```bat
build_setup.bat --iscc "C:\Tools\Inno Setup 6\ISCC.exe"
```

Результат: `release\setup.exe`, `release\setup.exe.sha256` и архив исходников. Сборка создаётся в новой папке из явного списка разрешённых файлов. `accounts`, tdata, API-ключи, базы, тексты рассылок, пользовательские настройки и логи в неё не копируются. В репозитории они также исключены через `.gitignore`.

## Выпуск обновления

1. Внесите изменения и поднимите `version` в `version.json`, например до `1.0.1`.
2. Закоммитьте изменения и отправьте их в ветку `main` на GitHub. Можно также выпустить версию отправкой тега `v1.0.1`.
3. Дождитесь зелёной сборки **Build and release Windows installer** во вкладке Actions. Она создаст публичный Release с `setup.exe` и контрольной суммой. Пользователи получат уведомление при следующей проверке.

При отправке `version.json` в `main` тег создаётся автоматически. Номер отправленного вручную тега должен совпадать с `version.json`. Для проверки до публикации запустите Actions вручную: установщик останется в Artifacts, уведомлений пользователям не будет. Черновики и предварительные релизы не предлагаются как обновления.

Можно собрать локально и приложить `setup.exe` вместе с `setup.exe.sha256` к обычному GitHub Release с тегом `vX.Y.Z`. Локальная публикация через GitHub CLI: `packaging\publish_release.ps1 -NotesFile путь_к_описанию.txt` после отправки тега.

Установщик не подписан коммерческим сертификатом. Windows может показывать издателя как неизвестного.
